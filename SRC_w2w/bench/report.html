A1_telemetry

A1 — Convergence telemetry

Not a speed feature; a trust feature. The sweep-cap warning used to be verbose-gated, so a production run could hit the 2000-sweep cap silently. Telemetry is now unconditional (sweeps, converged flag, last |dΩ|) — and it immediately settled the open question: the Rh3Si4 H120 production run did converge (1071 sweeps, |dΩ| = 8.2×10−8), so the baseline ΩI anchor is legitimate. Bonus finding: colored sweep order also converges in fewer sweeps (881 vs 1071).

A2_colored_omp

A2 — Colored (red-black) OpenMP sweeps

Gauss-Seidel sweeps parallelize across k-points of the same graph color (no two neighbours share one). First enablement produced NaN + a 13× slowdown — root-caused not to the OpenMP code but to homebrew OpenBLAS, which is unsafe under concurrent LAPACK callers (built without USE_LOCKING): its buffer allocator corrupts concurrent zheevd results and serializes the threads. Linking Apple Accelerate fixed both symptoms and is ~1.9× faster serially. The colored path itself is deterministic: 1-thread and 10-thread runs are bit-identical.

A3_adaptive_monitor

A3 — Adaptive convergence monitor

The exact ΩI monitor costs full-pool zgemms. The eigendecomposition inside each sweep already yields the free-block overlap sum for free, so the adaptive mode watches that signal every sweep and triggers the exact check only at plateaus — the converged ΩI is still exact-gated. With checks already throttled to every 10 sweeps the additional gain is modest (6.4% here); it grows wherever the exact check is relatively more expensive (larger pools, more frequent checking).

B1_binary_io

B1 — Transparent binary sidecars

The 3.3 GB text .mmn parses at ~2.5 MB/s. The readers now write a .bin stream sidecar (magic + dims header) after any text parse and reuse it while it is at least as new as the text file; validation failure falls back to text. Hand-off outputs are bit-identical text-vs-sidecar on both materials, and the sidecar also shrinks storage: mmn 3.3 GB → 1.3 GB, amn 340 → 103 MB.

A5_mixing

A5 — Zd mixing (SOR-style extrapolation)

Each Gauss-Seidel update eigendecomposes a per-k Gram matrix Zd; A5 optionally forms Zdeff = α·Zdnew + (1−α)·Zdhist. Damping (α<1) hurts Gauss-Seidel; extrapolation accelerates it strongly: α=1.7 converges in 197 sweeps instead of 881-1071 and lands at the lowest ΩI of any configuration — the extrapolation escapes the colored-order basin back to (slightly below) the serial optimum. α=1.9 overshoots. Fe parity exact.

D1_sigma_loop

D1 — One-process SOC σ-loop

Def unit 9 (second spin-component vectors; unit 19 for SP+SOC vsp) turns the per-spin w2w ×2 + w2waddsp chain into one process: the σ2 vectors are re-read in place, the overlap simply isn't re-zeroed (the spinor sum falls out), and per-σ projections land in separate amn column blocks — the zero-coefficient doubled-inwf construction of the original automated workflow is obsolete. Gates: amn blocks match the per-spin references at 2.4e-16 (an order-swap discriminator traced an apparent 6e-11 delta to vspup-vs-vspdn SCF residual in the reference chain); the σ-summed 3.3 GB mmn matches the w2waddsp file at 1.0e-12 — the print-rounding bound, i.e. the loop is more precise than the chain it replaces. Headline: the fully-automatic spinor model (AUTO 80×2 candidates) reproduces the original multi-step automated route: ΩI 840.05615289 vs 840.05615290, σmin 3.643e-4 vs 3.6425e-4.

Parity & the one caveat worth knowing

Fe reaches the identical fixed point under every configuration. On Rh3Si4 the colored sweep order converges to a different (equally valid) local optimum of the non-convex objective — 0.11% higher ΩI, but a 3.9× better SCDM anchor conditioning. Threaded runs are reproducible per-order; cross-order Ω equality is not the gate.
